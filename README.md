# S2S-RAG-POC

A minimal browser-based Voice-to-Voice POC for a health-insurance policy assistant. One
realtime speech-to-speech model (OpenAI Realtime API over WebRTC) explains a single policy
PDF to the user, answers clarifying questions strictly from that document via a
`search_policy` tool, and lets the user interrupt at any time.

## Architecture

```
Browser (React)                         Backend (Node/Express)              OpenAI
 |  1. GET /api/session ─────────────────────▶ create ephemeral session ───▶ Realtime API
 |  ◀──────────────────── client_secret ───────────────────────────────────|
 |
 |  2. WebRTC SDP offer/answer + mic audio  ────────────────────────────────▶ Realtime model
 |     (session config carries system prompt + search_policy tool schema)
 |
 |  3. Bot speaks predefined greeting, explains the policy. Server-side VAD
 |     lets the user interrupt at any time — no custom barge-in logic needed.
 |
 |  4. User asks a question ── audio ────────────────────────────────────────▶ model
 |  ◀── data channel: response.function_call_arguments.done (search_policy)
 |
 |  5. Browser relays the question to POST /api/search-policy ──▶ backend
 |     embeds question, cosine-similarity search over local vector index ──▶ evidence[]
 |     ◀── { evidence, sufficient }
 |
 |  6. Browser sends function_call_output back over the data channel ───────▶ model
 |
 |  7. Model answers using ONLY that evidence, or the fixed fallback
 |     sentence if sufficient = false ◀── audio ─────────────────────────────
 |
 |  8. Repeat 4–7. Predefined closing when done, then session ends.
```

The browser talks to OpenAI directly over WebRTC for low-latency audio, but the real
`OPENAI_API_KEY` and the policy vector index never leave the backend — the browser only ever
sends/receives an ephemeral token and plain question/evidence text.

## Project structure

```
backend/
  src/
    index.ts              # express app, wires retriever + routes
    config.ts              # env var loading
    logger.ts               # structured console logs (session/tool events)
    prompt.ts                # system prompt, tool schema, greeting/closing/fallback text
    routes/
      session.ts             # POST /api/session -> mints ephemeral Realtime token
      searchPolicy.ts         # POST /api/search-policy -> RAG lookup
    rag/
      retriever.ts            # PolicyRetriever interface + LocalJsonPolicyRetriever
      embeddings.ts            # OpenAI embeddings helper
      ingest.ts                 # policy.pdf -> chunks -> embeddings -> policy-index.json
      generateSamplePdf.ts       # optional: generates a small sample policy PDF for testing
  data/
    policy.pdf              # your policy document (gitignored — you provide/generate it)
    policy-index.json        # generated by `npm run ingest` (gitignored)
frontend/
  src/
    App.tsx
    realtime/
      useRealtimeSession.ts   # WebRTC connection, data channel, tool-call relay
      toolHandlers.ts          # calls to backend /api/session and /api/search-policy
      types.ts
    components/
      Controls.tsx
      TranscriptPanel.tsx
```

## Environment variables

**`backend/.env`** (copy from `backend/.env.example`):

| Var | Purpose |
|---|---|
| `OPENAI_API_KEY` | Real API key. Server-side only. |
| `REALTIME_MODEL` | Realtime model id (default `gpt-realtime`). |
| `EMBEDDING_MODEL` | Embedding model for RAG (default `text-embedding-3-small`). |
| `REALTIME_VOICE` | Voice for the spoken responses (default `alloy`). |
| `PORT` | Backend port (default `8787`). |
| `FRONTEND_ORIGIN` | Allowed CORS origin (default `http://localhost:5173`). |
| `RETRIEVAL_SCORE_THRESHOLD` | Min cosine similarity to count as sufficient evidence (default `0.72`). |
| `RETRIEVAL_TOP_K` | How many chunks to return per query (default `4`). |

**`frontend/.env`** (copy from `frontend/.env.example`):

| Var | Purpose |
|---|---|
| `VITE_BACKEND_URL` | Base URL of the backend (default `http://localhost:8787`). |

## Local setup

```bash
# 1. Backend
cd backend
npm install
copy .env.example .env    # then edit .env and set OPENAI_API_KEY

# 2. Provide a policy document
#    Option A: drop your own PDF at backend/data/policy.pdf
#    Option B: generate a small sample policy for testing
npm run generate:sample-pdf

# 3. Build the RAG index from the PDF (re-run any time policy.pdf changes)
npm run ingest

# 4. Start the backend
npm run dev
```

```bash
# 5. Frontend (separate terminal)
cd frontend
npm install
copy .env.example .env
npm run dev
```

Open the printed Vite URL (default `http://localhost:5173`), click **Start session**, allow
microphone access, and talk.

## End-to-end test instructions

1. With both servers running, open the frontend and click **Start session**.
2. Confirm the bot speaks the predefined greeting, then begins explaining the policy
   (coverage, waiting periods, exclusions, claims process — using the sample PDF's sections
   if you used `generate:sample-pdf`).
3. **Interrupt test**: while the bot is mid-sentence, start speaking a question (e.g. "What's
   the waiting period for pre-existing diseases?"). Confirm it stops talking and answers your
   question instead of finishing its sentence.
4. **Grounded-answer test**: ask something answerable from the document, e.g. "How long do I
   have to submit a reimbursement claim after discharge?" Confirm the transcript panel shows
   a `search_policy(...)` tool-call entry followed by a spoken answer consistent with the
   policy text (30 days, per the sample).
5. **Fallback test**: ask something the policy document does not cover, e.g. "Does this
   policy cover travel insurance abroad?" Confirm the bot responds with exactly: *"I don't
   find that information in the policy document available to me, so I don't want to provide
   an inaccurate answer."*
6. **Closing test**: once you're done asking questions, say something like "That's all,
   thanks" and confirm the bot gives the predefined closing statement.
7. Click **End session** and confirm the mic indicator turns off and the connection closes.
8. Check the backend terminal — you should see structured JSON log lines for
   `session_created`, `tool_call`, and `tool_result` (with `sufficient`/`chunkCount`) for
   every question asked.

## Swapping the RAG implementation

Everything routes through the `PolicyRetriever` interface in
[`backend/src/rag/retriever.ts`](backend/src/rag/retriever.ts):

```ts
interface PolicyRetriever {
  search(question: string): Promise<{ evidence: PolicyEvidence[]; sufficient: boolean }>;
}
```

To move to OpenAI's hosted file/vector search, Pinecone, pgvector, etc., write a new class
implementing this interface and swap the instantiation in `backend/src/index.ts` — no changes
needed to routes, the realtime tool schema, or the frontend.

## Notes / things to verify against current OpenAI docs

The OpenAI Realtime API's exact endpoint shapes (`/v1/realtime/client_secrets` response
fields, the WebRTC SDP exchange URL/params) have changed across API iterations. This POC was
written against the ephemeral-client-secret + `POST https://api.openai.com/v1/realtime` SDP
exchange pattern — if OpenAI's docs show different field names or endpoints at the time you
run this, adjust `backend/src/routes/session.ts` and
`frontend/src/realtime/useRealtimeSession.ts` accordingly; both are small, isolated, and
clearly commented at the relevant lines.
